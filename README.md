# GFK Transport LLC website

A complete marketing and lead-generation website for GFK Transport LLC.
USDOT 2367819, MC 812027.

Static HTML generated by a small Node script. No frameworks, no npm
dependencies, no database. It loads fast on a phone with one bar of signal at a
truck stop, which is where a fair share of this audience actually is.

---

## Quick start

```bash
node tools/make-images.mjs   # generate favicons and the share image (once)
node build.mjs --watch --serve
```

Then open <http://localhost:3000>. Edits to `site.config.js`, `src/`, or
`static/` rebuild automatically. Refresh the browser to see them.

Node 18 or newer. Nothing to install.

| Command | What it does |
| --- | --- |
| `npm run build` | Build once into `dist/` |
| `npm run dev` | Build, watch for changes, serve on port 3000 |
| `npm run check` | Build and exit non-zero if any placeholder is unfilled. Good for CI |
| `npm run images` | Regenerate the PNG icons and Open Graph image |

## Editing the site

**Almost everything lives in [`site.config.js`](site.config.js).** Phone number,
email, address, hours, services, FAQ entries, driver requirements, and coverage
area are all there. Change a value, rebuild, done. You should not need to open
the HTML for routine updates.

That file is the single source of truth on purpose. The company name, address,
and phone number appear on every page and in the structured data. Local search
ranking penalizes inconsistency between those, so they are defined once and
rendered everywhere from that one definition.

### Common edits

**Change the phone number**
`site.config.js` → `contact.phone`. Updates the top bar, both footers, every
call button, the structured data, and the `tel:` links.

**Add or remove a service**
`site.config.js` → `services`. Each entry needs `slug`, `icon`, `name`, `short`,
`body`, and `details`. Valid `icon` values are listed at the top of
[`build.mjs`](build.mjs) in the `ICONS` object. Adding one entry updates the
homepage grid, the services page, the footer links, the quote form dropdown, and
the structured data.

**Add an FAQ**
`site.config.js` → `faq`. Each new question is added to the page and to the
`FAQPage` structured data that makes questions eligible to appear directly in
Google results.

**Change the navigation**
`site.config.js` → `nav`.

### Adding a new page

1. Create `src/pages/your-page.html`
2. Start it with a meta block:

```html
<!--meta {
  "title": "Page title for the browser tab and search results",
  "description": "150 to 160 characters. This is the snippet Google shows.",
  "path": "/your-page/",
  "breadcrumb": "Your page",
  "priority": 0.6,
  "changefreq": "monthly"
} -->
```

3. Write the body. It goes inside `<main>`. Do not write `<html>`, `<head>`, the
   header, or the footer, since the layout supplies those.
4. Rebuild. The page is written to `dist/your-page/index.html` and added to
   `sitemap.xml` automatically.

Add `"noindex": true` to keep a page out of search results and the sitemap
(used by `/thank-you/` and the 404 page).

### Template syntax

| Syntax | Meaning |
| --- | --- |
| `{{ company.legalName }}` | Insert a config value, HTML-escaped |
| `{{{ html.serviceCards }}}` | Insert generated HTML, unescaped |
| `{{> header }}` | Include a partial from `src/partials/` |
| `{{ $.years }}` | A computed value. See `computed` in `build.mjs` |

Computed values available as `$.*`: `year`, `years`, `siteUrl`, `phoneHref`,
`phoneDigits`, `addressLine`, `mapsUrl`, `emailSafety`, `emailCareers`.

## The forms

Three forms ship with the site:

| Form | Page | Field name |
| --- | --- | --- |
| Quote request | `/quote/` | `quote` |
| Driver application | `/drivers/` | `driver-application` |
| General contact | `/contact/` | `contact` |

Where they post is controlled by `site.config.js` → `forms`. Set this to match
where you actually deploy, because a form pointed at the wrong provider fails
silently: the visitor sees a success page and you never get the lead.

```js
forms: {
  provider: 'netlify',   // Netlify Forms. No endpoint, no backend, Netlify hosting only.
  // or
  provider: 'external',  // Anywhere else. Posts to the endpoint below.
  endpoint: 'https://formspree.io/f/YOUR_FORM_ID',
}
```

`npm run build` prints a loud warning when forms are not configured.

Every form carries a hidden `form-name` input so you can tell which one fired,
plus a honeypot field that catches unsophisticated spam bots. In `external`
mode it also sends `_subject`, and both `_next` and `redirect` pointing at
`/thank-you/`, which covers Formspree and Web3Forms respectively. Each provider
ignores the field it does not recognize.

**After the first deploy to Netlify, do this:**

1. Netlify dashboard → your site → **Forms**. The three forms appear once the
   site has been deployed and each form has received at least one submission.
2. Submit a test through each form so they register.
3. **Forms → Settings → Form notifications → Add notification → Email
   notification.** Point quote requests at the address that someone actually
   watches during the day. A quote sitting unread in a dashboard is a lost load.
4. Consider adding a second notification to a phone via a Netlify webhook to
   Zapier or Make if you want an SMS on new quote requests.

### If you are not using Netlify

The forms are plain HTML POSTs, so any form service works. Replace the
`data-netlify`, `netlify-honeypot`, and hidden `form-name` attributes with what
your provider needs, and point `action` at their endpoint:

- **Formspree**: `action="https://formspree.io/f/YOUR_ID"`
- **Basin**, **Getform**, **Web3Forms**: same pattern
- **Your own server**: `action="/api/quote"` and handle the POST

Keep `action` pointing somewhere that ends at `/thank-you/` so the success page
still shows.

## Deploying

### Netlify (recommended, and what the config targets)

1. Push this folder to GitHub.
2. Netlify → **Add new site** → **Import an existing project** → pick the repo.
3. Netlify reads `netlify.toml`, so build command and publish directory are
   already set. Just click deploy.
4. Add your domain under **Domain management**. Netlify provisions HTTPS
   automatically.

### Vercel

`vercel.json` carries everything: build command, `outputDirectory: "dist"`,
security headers, and redirects. Import the repo and deploy, no dashboard
configuration needed.

Two things to know, because Vercel ignores every Netlify-specific file in this
repo:

- **`netlify.toml`, `static/_headers`, and `static/_redirects` do nothing here.**
  Their contents are duplicated in `vercel.json`. If you change a security
  header or a redirect, change it in **both** files or the two hosts will drift.
- **Netlify Forms does not exist on Vercel.** Set `forms.provider` to
  `'external'` and give it an endpoint, or all three forms are dead.

### Cloudflare Pages

Build command `npm run images && npm run build`, output directory `dist`.
`_headers` and `_redirects` are read natively. Set `forms.provider` to
`'external'`.

### Any other static host

Run `npm run images && npm run build` and upload the contents of `dist/`.
You will need to port `static/_headers` and `static/_redirects` to your host's
equivalent, and configure it to serve `404.html` for missing pages.

## After launch

The website is one piece. These are the rest, roughly in order of how much
freight they bring in for a carrier this size.

1. **Google Business Profile.** Free, and for a local carrier it usually
   outperforms the website itself. Claim it at
   <https://business.google.com>, use the exact same name, address, and phone as
   `site.config.js`, pick the "Trucking company" category, and add photos of
   real equipment.
2. **Google Search Console.** Verify the domain at
   <https://search.google.com/search-console> and submit
   `https://yourdomain.com/sitemap.xml`. Then put the verification token in
   `site.config.js` → `site.googleSiteVerification`.
3. **Bing Webmaster Tools.** Same idea, imports directly from Search Console.
4. **Email on your own domain.** The site currently uses
   `gfktransport@frontier.net`, which works but reads as a personal ISP account
   to anyone vetting you. `dispatch@gfktransport.com` reads as a real company,
   and it survives changing internet providers. Google Workspace or Microsoft
   365, about $6 to $7 per user per month. Change one line in `site.config.js`
   when you have it.
5. **Analytics.** Put a GA4 measurement ID in `site.config.js` →
   `site.googleAnalyticsId` and the tag renders automatically. If you enable it,
   add the Google domains to the `Content-Security-Policy` line in
   `static/_headers` or the script will be blocked.
6. **Carrier directories.** Make sure your listing is accurate on the FMCSA
   SAFER record, DAT, Truckstop, Carrier411, and Highway. Brokers check these
   before they check your website.
7. **Photos.** Replace `static/og.png` with a real 1200 by 630 image showing
   your equipment. Add photos of your trucks to the homepage and services page.
   Nothing builds trust in this industry like a picture of the actual truck.

## Maintenance

- **Yearly:** the copyright year updates itself, but re-read the About page and
  the driver pay figures. Both go stale quietly.
- **When insurance renews:** update the limits in `site.config.js` →
  `authority.insurance`.
- **When you add equipment:** add a service entry, or update `details` on an
  existing one.
- **Never let the phone number drift** between the site, Google Business
  Profile, and directory listings.

## Notes on how this was built

- No fabricated statistics, testimonials, or customer counts. Everything
  asserted on the site is either verifiable (the DOT and MC numbers, the founding
  year) or a commitment the company controls (same-day quotes, updates at
  pickup and delivery). Invented trust signals are a liability when a broker
  vets you, so there are none.
- Accessibility is built in rather than retrofitted: skip link, visible focus,
  keyboard-operable menu, real form labels, AA contrast, reduced-motion support.
  See `/accessibility/`.
- The site works with JavaScript disabled. The menu, the FAQ accordion, and all
  three forms are native HTML.
- Security headers including a strict Content Security Policy are in
  `static/_headers`.
